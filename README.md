# my-market-app

Это мультимодульный проект с аутентификацией и авторизацией.Проект состоит из двух модулей: реактивное MVC-приложение(
WebFlux+R2DBC), реактивный RESTfull сервис для обработки платежей.

## Модуль market-mvc

- В данном проекте реализована концепция 'MVC', но построенная на базе реактивной модели с ипользованием реактивного
  веб-стека 'WebFlux' и реактивного доступа к данным 'R2DBC'.
- Cоответственно присутствует как frontend-часть на базе шаблонизатора Thymeleaf, так и backend-часть.
- Это приложение позволяет пользователю просматривать товары из каталога на базе гибкого динамического поиска.
- Далее, если товар заинтересовал - можно положить его в корзину в нужном количестве, после чего, например, оформить
  заказ на покупку через взаимодействие с сервисом платежей 'payment-service'.
- Также присутствует функционал для добавления новго товара в каталог с его изображением.
- Для взаимодействия с сервисом платежей 'payment-service' был сгенерирован http client по написанной Open Api
  спецификациии.
- Для уменьшения издержек на частые запросы в БД , часто используемые данные-товары были закешированы в сторонней
  системе 'Redis'.


1. #### Модуль работы с товарами

Используются шаблоны страниц: item,items,newItem,newImage.

- ```GET /?search=[search]&sort=[sort]&pageNumber=[pageNumber]&pageSize=[pageSize]``` - для динамического поиска товаров
- ```GET /items?search=[search]&sort=[sort]&pageNumber=[pageNumber]&pageSize=[pageSize]``` - аналогично(алиас).
- ```POST /items?id=[id]&search=[search]&sort=[sort]&pageNumber=[pageNumber]&pageSize=[pageSize]&action=[action]``` -
  для изменения кол-ва в корзине(сл страницы товаров)
- ```POST /items/{id}?action=[action]``` - для получения товара.
- ```POST /items/{id}?action=[action]``` - для изменения кол-ва в корзине(со страницы товара)
- ```GET /items/new``` - для показа формы добавления товара(деталей).
- ```POST /items/new``` - действие добавления товара(деталей).
- ```GET /items/images/new``` - для показа формы добавления картинки для товара.

2. #### Модуль работы с корзиной

Для сохранения состояния корзины между запросами используется сессия, страница шаблона - cart.html

- ```GET /cart/items``` - для получения товаров в корзине и проверки баланса на счете через сервис платежей '
  payment-service'.
- ```POST /cart/items?id=[id]&action=[action]``` - для изменения кол-ва в корзине(со страницы корзины).

3. #### Модуль работы с заказами

Тут используется имитация оформления заказа - показ страницы заказа, шаблоны страниц: order.html, orders.html

- ```GET /orders``` - для получения всех заказов
- ```GET /orders/{id}?newOrder=[newOrder]``` - для получения заказа
- ```POST /buy``` - для оформления(создания) заказа через взаимодействие в сервисом платежей 'payment-service'.

4. #### Система безопасности

Система безопасности включает в себя:

- Регистрация - новый пользователь(гость), может зарегестрироваться в системе, чтобы проходить процедуру аутентификации.
- Аутентификация - предварительно зарегестрированный пользователь интернет-магазина использует форму входа 'Login',
  чтобы получить доступ к защищенным рерурсам приложения.
- Авторизация - пользователь имеет роль, которая определяет его привелегии. На текущий момент, у пользователя может быть
  роль 'USER'(стандартная).
- Сервер Авторизации(OAUTH2.0) - 'market-mvc' выступает как зарегестрированный клиент в 'client credentials flow'
  для получения токена досупа 'Access token'
- Токен доступа(Access token) - содержит информацию определенную в 'scope', в том числе и роли.
  Токен передается с запросом при взаимодействии с сервисом оплаты 'payment-service'

## модуль payment-service

- В данном проекте реализована концепция 'RESTfull', построенная на базе реактивной модели с ипользованием реактивного
  веб-стека 'WebFlux' и реактивного доступа к данным 'R2DBC'.
- Данный сервис используется как сервер для запросов от клиента - 'market-mvc'.
- Это приложение позволяет получать баланс пользователя и проводить оплату через транзакцию в клиентском приложении '
  market-mvc'.
- Серверная часть (контроллеры и Дто) сгенерирована по написанной Open Api спецификациии.


1. #### Модуль для доступа к счету пользователя

Используются шаблоны страниц: item,items,newItem,newImage.

- ```GET /api/payments/accounts/{accountId}``` - для получения информации о счете пользователя(баланса).

2. #### Модуль для доступа к сервису оплаты.

Для сохранения состояния корзины между запросами используется сессия, страница шаблона - cart.html

- ``` POST /api/payments/pay ``` - для оплаты , тоесть создается транзакция оплаты и если все ок, происодит списание со
  счета.

3. #### Система безопасности

Система безопасности включает в себя:
- Внутренней аутентификации,авторизации в этом сервисе нет, так как он не имеет пользовательского интерфейса и предполагается взаимодействие только через REST API.
- Сервер Авторизации(OAUTH2.0) - 'payment-service' выступает как Сервер ресурсов в 'client credentials flow'
  ,получив токен доступа 'Access token'  при запросе, он проверяет его через сервер авторизации и предоставляет доступ.
- Токен доступа(Access token) - содержит информацию определенную в 'scope', в том числе и роли.
  Токен передается с запросом от сторонних сервисов с целью получения доступа. В нашем случае 'market-mvc'.


### Сервер авторизации (Keycloak)

В качестве сервера авторизации я выбрал Keycloak, на котором:
- Настроил пространство 'market-payment'
- Зарегестрировал клиента  'market-mvc'
- Создал роль пространства, которую связал с клиентом.

> - Как сервер авторизации в терминологии OAUTH2.0 использовал Keycloak.

### Сборка

Сборка осуществляется с помощью инфраструктуры Docker с использованием Docker compose.

- В корневой папке многомодульного проекта вы найдете файл для сборки:  ```compose.yaml```
  В нем описаны все службы(контейнеры), которые необходимы для работы приложения в целом.
- В папке каждого модуля располагаются файлы сборки образа:```market-mvc/Dockerfile```,```payment-service/Dockerfile```.
  Для сборки и запуска приложения(всех сервисов) просто запустите из корня проекта следующую команду.

  ```
  docker compose up -d
  ```

- В результате поднимятся 2 базы данных Postgres, сервис оплаты и приложение интернет-магазина, а также
  система кеширвоания Redis во внетренней сети Docker и сервер авторизации Keycloak.
